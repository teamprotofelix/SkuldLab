## 수동 확인 순서

1. 첫 화면 LAB MAP에서 스쿨드를 선택하고 연금 공방으로 이동, 따라보기를 확인.
2. 모듈 버튼으로 전경과 임무를 열고 세계수·포션을 완료.
3. 조립 설계도를 저장하고 시험 로봇이 나타나는지 확인.
4. FLIGHT VIEW 출격 → 자동 감상 → 수동 전환 → 방향키/터치 → 일시정지 → 세 항로 전환.
5. 창 전환/모달 열기 시 입력이 해제되고 진행이 멈추는지 확인.
6. 새로고침 후 설계도·여권 보존, 최초 온라인 방문 후 오프라인 열람 확인.
7. 새 릴리스에서 ‘새 버전 적용’으로 업데이트하고 기록 보존 확인.

## 3.0 병합 검토

- 사용자 흐름: 설계 저장 → 동력 분배 시험 → 세 항로 중 선택 → 밤페이 출격 → 별조각 3개 회수 → 귀환 및 연구 일지 기록. 성운 항로는 실제 Chromium UI에서 밤페이 설계 80점, 172 AU, 별조각 및 보상 3점을 확인했다. 다른 두 항로의 고정과 설계에 따른 조종 차이는 모델 검사로 확인했다.
- 저장: 이전 세 키를 처음 열 때 IndexedDB로 복사한다. Chromium에서 같은 DB를 연 두 연결의 동시 쓰기, 트랜잭션 중단 시 원본 유지, 잘못된 JSON 거부, 미리보기·명시적 복원 후 일지 재로딩을 확인했다. 이전 백업 재적용과 귀환 ID 중복은 단위 검사로 확인했다.
- 화면: Chromium의 1440·768·390·320px 프레임에서 지도·작업대·비행·일지의 가로 넘침과 수동 조종 버튼을 확인했다. 768px에서 발견한 헤더와 지도 넘침을 수정했다. 이 결과는 실기기 터치 검증을 대신하지 않는다.
- PWA: 로컬 2.2.1에서 3.0으로 ‘새 버전 적용’을 확인했다. 연구 일지 작성 후 새로고침, 추가 캐시 갱신, 미리보기 서버 중단 후 재접속에서도 일지가 표시됐다.
- 내장 이미지 생성으로 제작실·격납고·리액터 상세 장면 3개를 새로 생성했다. 각각 1672×941 WebP이며 출처·크기·SHA-256은 자산 명세와 이미지 프롬프트를 참조한다. 기존 시트의 대기 프레임과 CSS 표시등으로 상태를 연출한다. 새 전용 동작 시트는 포함하지 않았다. 상세 이미지는 구역 입장 때만 요청하며 실패 시 기존 이미지를 사용한다.
- 자동 검사: `npm test` 27개, `npm run check`, `npm run verify`, `git diff --check`. 별도 Playwright 스크립트는 이 실행 환경에서 Chromium 소켓 제한으로 실행하지 못했다. 위 브라우저 결과는 별도의 공유 Chromium에서 확인했다. 실기기 PWA 설치·Safari, 콜드 네트워크 전송과 장시간 성능은 미측정이다.
- 롤백: 이전 코드는 원본 localStorage 키를 읽는다. 3.0 이후 작성한 기록은 IndexedDB에 남아 다시 3.0을 열면 표시된다. 이전 버전으로 돌아가야 하면 먼저 연구소 도움말에서 전체 JSON을 백업한다.
